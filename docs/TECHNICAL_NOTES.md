# Технические заметки — Logovo Video Downloader

Python 3.12, FastAPI, PostgreSQL, nginx, yt-dlp. Видеофайлы новых заданий **не сохраняются
на сервере**. Анализатор получает метаданные, сервер-посредник передаёт исходные байты,
а браузер хранит дорожки в OPFS на устройстве и собирает итоговый файл библиотекой
Mediabunny без декодирования и перекодирования. Воспроизведение не требуется.

## Запуск

В подготовленной локальной копии уже есть `.env` со случайным паролем базы данных.
В новой копии создайте `.env` из `.env.example` и замените пароль на случайную строку
из букв и цифр. Либо выполните `python -m app.bootstrap`.

```sh
docker compose up -d --build
```

Открыть: http://localhost:8080. Порт по умолчанию доступен только локально.
Для Linux-сервера настройте внешний HTTPS-прокси, `PUBLIC_ORIGIN=https://ваш-домен`
и `COOKIE_SECURE=true`. HTTPS необходим для локального файлового API браузера
(localhost — допустимое исключение). Не публикуйте порты базы, API и egress.

Остановка: `docker compose down`. Без `-v`: volumes сохраняют сессии и предыдущие задания.
Node.js нужен при сборке Docker для упаковки JavaScript и при работе yt-dlp с YouTube.
Библиотека закреплена package-lock.json, браузер загружает её с нашего сервера, без CDN.

## Интерфейс

Подробная матрица возможностей и ограничений: [SUPPORTED_SOURCES.md](../SUPPORTED_SOURCES.md).

После вставки ссылки автоматически начинается анализ; видны результат «Можно скачать»
или причина отказа. Кнопка «Скачать» сначала серая, после успешной проверки — зелёная.

Под полем URL показано распознавание плеера: название (или несколько названий),
отдельно библиотека hls.js/dash.js и обнаруженный тип потока HLS/DASH/HTTP-файл.
Данные получаются по URL плеера, открытым скриптам/HTML и метаданным каталога,
без запуска видео. Если название неизвестно, показано «Плеер: не определён».
Прямая ссылка на файл/манифест не выдаётся за конкретный плеер. Версии не угадываются,
а распознавание не означает подтверждённую возможность скачивания. Диагностика
сохраняется даже при ошибке анализа; после очистки ссылки строка скрывается.
Одно нажатие запускает получение данных, локальную сборку и сохранение. Во время работы
кнопка «Идёт загрузка» отключена. После завершения поле ссылки очищается.
В списке доступны прогресс, пауза, продолжение, отмена и постоянное описание сохранения.

Общий индикатор очереди находится под строкой папки сохранения, перед карточкой
текущего видео. Он показывает число готовых видео, текущий номер и этап. В карточке
серии показан её собственный прогресс; на этапе анализа/при неизвестном размере
используется индикатор без выдуманного процента. После завершения остаётся итог очереди.

Ошибки анализа, передачи, сборки, сохранения и непредвиденные ошибки приложения
показываются в модальном окне с названием видео и причиной. Для пустой причины есть
сообщение о неизвестной ошибке. При ошибке очередь останавливается, не запускает
следующие серии и предлагает повторить оставшиеся задания. Обычные пауза/отмена не
вызывают модалку ошибки. У запросов API тайм-аут 20 секунд; непредвиденный серверный
сбой возвращается как JSON с безопасным кодом для диагностики. Закрытый/аварийно
завершённый браузер показать модалку в момент сбоя, разумеется, не может.

Качество по умолчанию 1080p, сохраняется в cookie. Если точного нет — ближайшее выше,
если выше нет — максимальное ниже. Вертикальные видео сравниваются по короткой стороне.
Настройки языка нет: исходные дорожки копируются, перевод не выполняется.

## Каталоги серий и плейлисты

Страницы `old.yummy-ani.me/catalog/item/...` распознаются до обычного извлечения видео.
Приложение получает список озвучек и серий и открывает модальное окно. Поддержан плеер
CVH; добавлен экспериментальный API-адаптер Kodik и обработчик открытых настроек Alloha.
Kodik на контрольной серии отвечает HTTP 500, а динамическая версия Alloha пока
не поддерживается: выбор серии не гарантирует доступность потока. Это не универсальный
обход ограничений: авторизация, CAPTCHA и DRM не обходятся. Поддерживаемые yt-dlp
плейлисты также открываются как список видео, если источник возвращает их метаданные.

По умолчанию выбраны все доступные серии одной озвучки; можно указать номера через
запятую. Контейнер: исходный, MP4 или MKV. Меняется только упаковка дорожек, без
перекодирования; несовместимый кодек вызовет понятную ошибку локальной сборки.

После подтверждения создаются отдельные задания `pending`, максимум 100 незавершённых
в сессии. Они не занимают воркеры до своей очереди. Анализ и скачивание идут последовательно,
каждая серия сохраняется отдельным файлом на устройство. Пауза очереди приостанавливает
текущую серию и не запускает остальные; отмена серии не удаляет остальные задания.
Очередь хранится в БД с привязкой к анонимной сессии 7 дней. После перезагрузки страницы
её надо запустить кнопкой «Скачать очередь». Фон при закрытии/блокировке мобильного браузера
не гарантируется. Браузер может запросить разрешение на множественные загрузки.

Доступность и качество проверяются для каждой серии. Озвучка не подменяется автоматически.
Подписанные ссылки CVH обновляются при возобновлении; метаданные и поток запрашиваются
через один egress-прокси, поскольку CDN может привязывать ссылки к IP сервера.

## Сохранение и платформы

Требуется современный браузер с OPFS, IndexedDB, Fetch Streams. Chrome/Edge на Windows
и macOS, современные Safari и браузеры Android могут обрабатывать медиа локально.
Это не обещание одинаковой работы на всех версиях ОС: размер доступного хранилища,
ограничения памяти, энергосбережение и экспорт файла зависят от браузера и устройства.

По умолчанию «Скачать» использует папку загрузок из настроек браузера без собственного
диалога выбора файла. Если в браузере включено «Всегда спрашивать место сохранения»,
его системный диалог всё равно появится — сайт не может отключить эту настройку.

Под ссылкой есть строка «Куда скачать:» и меню «…». В браузерах с `showDirectoryPicker`
можно выбрать папку один раз; следующие файлы записываются туда автоматически, пока
действует разрешение. При совпадении имени создаётся вариант «имя (1).mp4», существующие
файлы не перезаписываются. Меню позволяет вернуться к папке браузера по умолчанию.
Сайт знает только имя выбранной папки: **абсолютный путь API не раскрывает**.
В Safari/iPhone выбор папки остаётся в настройках браузера/системном окне.

Режим и обозначение папки сохраняются в cookie `dav_destination` при первом посещении
и после изменения, а также в таблице `session_preferences`, связанной с ID сессии.
Файловое разрешение хранится только в IndexedDB, не в cookie/БД сервера. Сам текст пути
не даёт разрешения на запись. Если браузер отозвал доступ, нужно повторно выбрать папку.

В Safari/iPhone готовый файл сначала находится локально в данных сайта. Приложение
автоматически передаёт его менеджеру загрузок через ссылку Blob. Браузер может потребовать
подтверждение; остаётся кнопка «Сохранить файл» для повторного экспорта без повторного
скачивания. Папку определяет браузер/системное окно. Сообщение «Передан в загрузки»
не означает подтверждения записи в конкретную папку. Выдуманные пути не показываются.

На iPhone нельзя гарантировать фоновую сборку при блокировке экрана. По возможности
запрашивается блокировка засыпания экрана. Полученные части сохраняются локально для
продолжения, но браузер может очистить данные сайта или лишить его квоты.

## Поддерживаемые потоки

- Готовые HTTP/HTTPS-файлы сохраняются без изменения исходного контейнера.
- Раздельные видео и звук объединяются локально в MP4, WebM или MKV, с исходными кодеками.
- Незашифрованные конечные HLS-плейлисты TS/fMP4 и простые DASH-списки сегментов
  загружаются в локальные части и собираются в браузере.
- Зашифрованный HLS, HLS с discontinuity/сменой заголовков, некоторые диапазоны DASH,
  DRM, прямые эфиры и плейлисты роликов не поддерживаются. Показывается причина.
- Закрытые аккаунты и импорт сторонних cookies не поддерживаются. Антибот, HTTP 403/429,
  географические ограничения и удаление видео обрабатываются отдельными сообщениями.
  Неизвестная причина не подменяется выдуманной точной диагностикой.

Проверка ссылки оценивает метаданные и плейлист, а не получает всё видео заранее:
ограничение или ошибка могут возникнуть позднее на конкретном сегменте. В таком случае
задание сохраняет ошибку и доступные локальные части. Поддержка сайтов зависит от yt-dlp
и доступности источника с IP сервера.

## Сессии, пауза и очистка

Одна анонимная сессия браузера содержит несколько заданий. Секрет сессии — в защищённой
HttpOnly cookie, его SHA-256 — в PostgreSQL. Сессия не удаляется по времени, даты создания
и последней активности сохраняются. Cookie продлевается на 400 дней при обращении к API;
браузер может удалить её раньше. Задания доступны только своей сессии.

На сервере у нового задания хранятся только выбранные потоки, временные URL, состояние,
прогресс и срок. Дорожки и результат — в OPFS, сведения и выбранный файловый дескриптор —
в IndexedDB. Это данные конкретного браузера на конкретном устройстве, не серверный архив.

MP4 и другие обычные файлы запрашиваются одним потоком, без искусственного деления по 4 МБ.
Данные записываются постепенно, без загрузки всего файла в оперативную память. Для HLS/DASH
сохраняются сегменты и байтовые диапазоны, заданные источником. Если источник требует Range,
прокси повторяет начальный запрос с диапазоном; если отдаёт частичные ответы, загрузчик
последовательно получает оставшиеся байты. Размер порций определяет источник. При отсутствии
валидатора в пределах одной непрерывной загрузки сверяется перекрытие соседних порций и размер;
это не заменяет надёжный идентификатор версии всего файла.

«Пауза» прекращает запросы и сохраняет локальные части. «Продолжить» проверяет идентичность
потоков, обновляет истёкшие URL и продолжает части через Range/If-Range при поддержке
источника. Незавершённые части без валидатора получаются заново, завершённые не скачиваются
повторно. Для единого MP4 без валидатора это означает повтор файла целиком. Если источник
игнорирует Range и возвращает полный файл, частичная копия заменяется, а не дополняется.
Сборка после паузы может начаться заново,
используя уже полученные дорожки. Разные вкладки координируются через Web Locks.

Пауза — 7 дней. При потере вкладки heartbeat истекает через 90 секунд и задание становится
приостановленным. После завершения временные серверные данные хранятся 1 час, история
с текстом сохранения остаётся. Локальные исходные части удаляются после успеха; резервный
итоговый файл для Safari хранится 7 дней и очищается при следующем посещении.
Отмена удаляет временные части, но оставляет запись «Отменено пользователем» в «Ваших
загрузках». Ошибки сохраняются вместе с причиной, даже после последующей отмены. История
не удаляется по истечении срока временных данных; удалить запись можно кнопкой «Убрать
из списка». Выбранный пользователем файл и копии в загрузках браузера сайт не удаляет.
Под названием показаны дата и время до минут в часовом поясе устройства. У успешной загрузки
это время завершения, у отмены или ошибки — время соответствующего события. Старые ошибки
не восстанавливаются в верхнем блоке при обновлении страницы. Продолжить сохранённую очередь
можно из раздела «Ваши загрузки». Автоматическая смена ссылки не создаёт запись об отмене.
Общая кнопка продолжения выбирает только ожидающие и приостановленные задания без ошибок;
серверные и локальные ошибки пропускаются. В модальных окнах ошибок проверки видео нет
кнопки повтора. При недоступности фонового обновления показывается ненавязчивое
«Восстанавливаем соединение…»: запросы повторяются автоматически, сообщение исчезает
после успешного обновления. Ошибки конкретной загрузки по-прежнему показываются отдельно.

При очистке данных сайта теряются локальные части и доступ к сессии. Источник может
удалить видео до истечения семидневного срока. Нельзя продолжить на другом устройстве:
полученные части находятся на исходном устройстве.

Готовые файлы старой версии не удаляются обновлением: их можно скачать или отменить
в списке. Новые задания не используют прежнюю серверную сборку.

## Ограничения и сеть

При первом посещении обязателен выбор в баннере cookie: «Принять всё», «Только необходимые»
или настройка запоминания качества и папки. Необязательные настройки не читаются и не
сохраняются до разрешения. Выбор хранится в cookie `dav_consent` 180 дней. Сессия и данные
скачиваний нужны для запрошенной функции и не отключаются этим переключателем. Реклама
и аналитика не добавлены. Отозвать разрешение можно через «Настройки cookie» внизу страницы:
удаляются cookie настроек, сохранённое разрешение папки из настроек IndexedDB и запись
предпочтений текущей сессии на сервере. История и выбранные файлы не удаляются. При отказе
качество и папку можно менять для текущей вкладки без запоминания между посещениями.

Баннер описывает техническое хранение, но не заменяет полноценную политику обработки
персональных данных, определение оператора и правовых оснований обработки. Перед публичным
запуском эти документы и сроки хранения нужно проверить отдельно.

`MAX_FILE_BYTES` — 5 ГиБ, `MAX_SESSION_JOBS` — 10 активных заданий,
`DOWNLOAD_WORKERS` — 2 параллельных процесса анализа. Фактический размер ограничен также
локальной квотой браузера. До скачивания проверяется оценка свободного места; при переполнении
показывается ошибка. Доступность кодека для воспроизведения на устройстве не гарантируется:
скачивание не перекодирует его.

API и worker находятся во внутренней Docker-сети. HTTP-запросы проходят через egress-прокси,
который разрешает только публичные IP и порты 80/443. Подключение закрепляется за проверенным
IP, блокируя DNS rebinding и запросы к локальным адресам через редиректы. Без Compose
сетевая изоляция отсутствует; отдельный запуск Python подходит только для разработки.

Изменения проверяют Origin и специальный заголовок; nginx ограничивает частоту запросов.
Технические журналы источников могут содержать подписанные ссылки — не публикуйте их целиком.

## Проверки

```sh
docker compose run --rm --no-deps api python -m pytest -q -p no:cacheprovider
```

Тесты используют отдельную SQLite-базу, не рабочие данные. Проверяют изоляцию сессий,
качество, CSRF/SSRF, локальный план без раскрытия URL, передачу частей без серверных файлов,
диапазоны, паузу, TTL и классификацию ошибок. Интеграционный HLS-тест генерирует двухсекундный
источник и подтверждает, что сервер получил только метаданные, не сохранив видео.

Таблица `session_preferences` создаётся автоматически при запуске обновления, без удаления
существующих сессий и заданий. Планы продолжают храниться в прежнем JSON-поле.
